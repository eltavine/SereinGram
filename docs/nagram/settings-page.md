# Nagram 设置页设计

本文件定义 Nagram 设置页的分栏、控件形式、顺序与说明文字。每个条目的上游处理点见 [上游处理点](upstream-hooks.md)，交付顺序见 [分步实施计划](implementation-plan.md)，需求来源见 [功能需求](requirements.md)。

条目编号（如 `C07`）是文档内标识，贯穿三份文档；稳定存储键在注册表中定义，不用编号代替。

## 1. 通用规则

1. **入口**：上游设置主页顶部（账号资料卡片之下、第一组设置之前）新增一行“Nagram”，使用 Nagram 单色图标。只新增这一处主页入口，挂钩位于 `settings/sections/settings_main.cpp` 的 `BuildSectionButtons`，作为其第一项。
2. **页面结构**：Nagram 首页是分栏列表，每个分栏是一个子页面（上游 `Settings::Section` + `SectionBuilder`）。子页面内用小标题分组，分组之间用上游分隔线。
3. **只展示已实现的条目**：条目随对应步骤的提交出现；没有消费者的键不注册、不显示、不进搜索。分栏在第一个条目落地前不显示。
4. **不提供恢复默认**：任何页面都没有单项、分组或全局重置按钮（沿用需求约定）。
5. **默认值**：开关默认关闭；数值与选项默认“跟随 Telegram”。默认状态必须与上游行为完全一致。
6. **标题措辞**：以用户看到的效果命名，开关统一用“隐藏… / 显示… / 关闭… / …前确认”。不在标题里写实现细节。
7. **说明文字**：只在以下情况加说明（分组下方的分隔说明，或单项下方一行）：生效时机不是立即、有作用范围限制、与其他条目有优先级关系、容易误解为服务端行为。下表“说明”列为空的条目不加说明。
8. **生效时机**：默认立即生效。需要重启的条目在右侧显示“重启后生效”标签，修改后弹出上游的重启确认框；需要重新打开页面的，在说明中写明。
9. **搜索**：每个条目以标题和关键词注册到上游设置搜索，搜索结果跳转并高亮该条目。关键词包含英文标题，便于中文界面下用英文搜索。
10. **三语**：所有标题、选项、说明同时提供英文、简体中文、繁体中文。

### 控件形式

| 形式 | 用途 | 上游控件 |
| --- | --- | --- |
| 开关 | 布尔选项 | `SectionBuilder::addButton`，带 `toggled` |
| 选项 | 有限枚举；右侧显示当前值，点击打开单选框 | `addButton` + `label` + `SingleChoiceBox` |
| 数值 | 百分比、毫秒、数量；右侧显示当前值，点击打开带滑块或输入框的对话框，首项固定为“跟随 Telegram” | `addButton` + `label` + 自定义 `GenericBox` |
| 文本 | 单行文本；右侧显示当前值或“默认” | `addButton` + `label` + 输入对话框 |
| 子页 | 结构化配置（列表、排序、规则） | `addSectionButton` 进入独立 Section |
| 动作 | 一次性操作（导出、导入、备份） | `addButton`，无状态 |
| 从属开关 | 依赖父开关的子项；父项开启时子项显示为禁用并保留原值 | 缩进的 `addButton`，`shown` / 禁用状态绑定父项 |

## 4. 不在设置页出现的内容

- 上游已有的能力（主字体、主题、缩放、文件夹标签样式、发送快捷键、自动下载、下载路径、通知内容开关等）继续使用上游入口。

- 需求中合并或排除的来源配置（见 [功能与配置目录](feature-catalog.md)）不单独出现。
